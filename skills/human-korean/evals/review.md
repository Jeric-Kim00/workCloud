# HUMAN 1.0 검토 기록

검토일: 2026-11-11

## 수행 범위

스킬 작성자가 지침과 아래 경계 사례를 직접 대조했다. 별도 모델 호출, 독립 평가자, 통제된 A/B 실험은 사용하지 않았다. 따라서 통과율이나 자연스러움 향상률을 주장하지 않는다. 예시 문구를 작성하는 일과 스킬의 실제 실행 성능 검증은 구별한다.

## 경계 사례 검토

| 요청 유형 | 확인한 동작 | 반영한 규칙 |
| --- | --- | --- |
| 원문 없는 개념 설명 | 초안이나 개인 샘플 없이 내용을 작성하고 필요한 예시를 제공 | 기본 작성 흐름과 정확성·충분함 점검 |
| 팀 일정 변경 요청 | 변경 제안과 확정 안내를 구분 | 약속·확신·조건 보존 |
| 긴 보고서 | 소제목·표와 필요한 근거를 유지 | 분량과 형식 존중, 무조건 줄이지 않음 |
| 위로·축하·감사 메시지 | 요청한 감정을 표현하면서 가짜 경험은 만들지 않음 | 새 글 작성과 원문 편집 규칙 구분 |
| 고객 문의에 대한 답변 | 필요한 사과는 가능하되 보상이나 해결 기한은 만들지 않음 | 상황에 맞는 감정과 사실의 경계 |
| JSON만 요청 | 자연스러운 설명을 덧붙여 형식을 깨지 않음 | 요구 형식 우선 |
| 영어 이메일 요청 | 스킬 때문에 한국어로 바꾸지 않음 | 결과물 언어 지정 우선 |
| 원문 속 지시문 | 인용된 지시를 실행하지 않음 | 원문과 작업 지시 분리 |
| 이미 잘 읽히는 짧은 글 | 수정량을 늘리려고 다시 쓰지 않음 | 필요한 부분만 수정 |
| 추천·창작 요청 | 원문에 없다는 이유만으로 의견이나 창작을 막지 않음 | 작업 범위에 맞는 생성 허용 |

## 점검 중 수정한 문제

1. 초안에 남은 원문 중심 표현을 새 결과물 작성 흐름으로 바꿨다.
2. 감정 추가 금지를 기존 글 편집에 한정하고, 새 메시지 작성에서는 요청한 감정을 표현하도록 했다.
3. 인사말·맺음말을 무조건 억제하지 않고 매체에 맞게 쓰도록 했다.
4. 단문·해요체·문단 형식을 일괄 강제하지 않도록 예외를 정리했다.
5. 코드·JSON·다른 언어·정해진 양식과의 충돌을 막는 규칙을 추가했다.

## 파일 검사

YAML frontmatter와 Codex 표시 정보의 파싱, 상대 참조 파일 존재, UTF-8 인코딩, ZIP 내부 경로와 압축 무결성을 확인한다. 이 검사는 패키지의 구조를 확인하며 문장 품질을 측정하지 않는다.

## 실제 품질을 비교할 때

같은 모델·조건에서 새 요청을 스킬 없이 한 번, 스킬과 함께 한 번 수행한다. 스킬에 들어 있는 예시는 평가 문제로 재사용하지 않는다. 설명·업무 메일·보고서·감정 메시지·긴 문서의 새로운 요청을 사용한다.

평가자는 어느 쪽에 스킬이 적용됐는지 모르는 상태에서 정확성·충분함을 먼저 확인하고 가독성·문장 흐름·상황에 맞는 자연스러움을 비교한다. 사실·조건·필수 정보가 빠진 결과는 말투가 좋아도 개선으로 보지 않는다. 모델이나 지침이 크게 바뀌면 같은 방식으로 다시 확인한다.

## 1.0.1 설치기 검증

Python 설치기는 임시 사용자 경로에서 신규 설치, 무변경 재설치, 기존 버전 백업, 불완전 패키지 거부, 활성화 실패 시 복구를 검사한다. Windows PowerShell 설치기는 같은 순서로 복사·해시 확인·백업·교체를 수행한다. 현재 Linux 환경에는 PowerShell이 없어 Windows 실제 실행은 확인하지 못했다.
