# Timely Partner Network (검토용)

Timely AI · Timely Router 통합 리셀러/총판 파트너 프로그램 검토 자료입니다.

| 파일 | 내용 |
|---|---|

| [demo/index.html](demo/index.html) | 파트너 프로그램 데모 웹 (한 페이지 안에 아래 네 화면) |

## 데모 화면

게시 주소: https://claude.ai/artifact/3yLjNeRUZbWvRJGR8iTn3b (조직 구성원만 열 수 있음)

| 화면 | 바로가기 | 내용 |
|---|---|---|
| 프로그램 소개 | `#home` | 새 파트너 / 기존 파트너 진입, 판매 제품, 혜택, 등급, 참여 절차, FAQ (할인율 수치는 표시하지 않음) |
| 로그인 · 회원가입 | `#login` `#signup` | 회사 이메일 인증(6자리 코드) 후 가입. ID 찾기 `#findid`, 비밀번호 찾기 `#findpw` |
| 파트너 신청 | `#apply` | 담당자 정보 → 회사 정보 → 파트너 프로필 → 동의·제출 (OpenAI 파트너 신청서 구성 참고) |

| 관리자 | `#admin` | 개요, 파트너 신청 심사(승인·보류·반려, 승인 시 파트너별 할인율 설정), 파트너 관리(등급·할인율 조정), 고객사 진행(본사 단계 처리), 딜 검토(승인·반려·보호 연장·동일 고객 합산), 리베이트 결정, 결정 기록 |

## 디자인 시스템

조직 기본 디자인 시스템인 [타임리 AI 디자인 시스템](https://claude.ai/artifact/TKYtZQh25DEXJooEKNHjji)을 그대로 씁니다.

- `components/bundle.css`: 토큰, 글자 클래스, Pretendard
- `components/bundle.js`: `window.Timely` React 컴포넌트. Button, Badge, Table, Modal, Tabs, Dropdown, TextInput, Checkbox, RadioButton, LabelContainer, DashboardSidebar를 사용합니다.
- 이 파일들은 게시할 때 디자인 시스템 아티팩트에서 복사합니다. 저장소에는 넣지 않았습니다.

## 회원 (데모)

| 기능 | 규칙 |
|---|---|
| 회원가입 | 회사 이메일만 허용(gmail·naver·daum·kakao 등 개인 메일 차단) → 6자리 인증 코드 → 이름·휴대폰·회사명·비밀번호·필수 동의 → 확인 팝업 → 가입 |
| 인증 코드 | 5분 유효, 재전송은 60초 뒤, 5회 틀리면 다시 받기 |
| 비밀번호 | 8자 이상, 영문·숫자·특수문자 모두 포함. 솔트를 붙인 SHA-256 해시로 저장(평문 저장 안 함) |
| 로그인 | ID = 회사 이메일. 5회 틀리면 5분 잠금 |
| ID 찾기 | 이름 + 휴대폰 번호 → 이메일 일부 가림(예: le*@hanbit-it.co.kr) |
| 비밀번호 찾기 | 회사 이메일 인증 코드 확인 → 새 비밀번호 → 확인 팝업 → 다시 로그인 |
| 로그인이 필요한 화면 | 파트너 신청, 파트너 포털 (관리자 화면은 페이지 편집 권한으로 판단) |

데모의 한계와 실제 서비스에서 바꿀 점:
- 인증 메일은 실제로 보내지 않습니다. 코드는 브라우저에서 만들어 화면의 "데모 메일함"에 보여 줍니다. 실제 서비스에서는 서버가 코드를 만들어 메일 발송 서비스로 보내고, 코드와 시도 횟수도 서버에서 검증해야 합니다.
- 비밀번호 해시 비교와 로그인 잠금이 브라우저에서 이뤄집니다. 실제 서비스에서는 서버에서 느린 해시(bcrypt, Argon2 등)로 처리해야 합니다.
- 계정은 claude.ai 사용자 한 명당 하나입니다(`accounts/<사용자>`).

## 고객사 진행 (PoC 스페이스 · 크레딧 지급)

모든 파트너에 공통으로 적용합니다. 고객사마다 아래 7단계를 한 줄로 보여 주고, 지금 누가 무엇을 해야 하는지 배지로 표시합니다(예: "본사 처리 대기 · PoC 스페이스 전달").

| 구분 | 단계 | 기록 주체 | 입력 항목 | 앞 단계 조건 |
|---|---|---|---|---|
| PoC | ① 고객사 협의 | 파트너 | 협의일, 메모 | - |
| PoC | ② PoC 스페이스 요청 | 파트너 | 스페이스 주소, 지급 희망일 | ① |
| PoC | ③ PoC 스페이스 전달 | 본사 | 전달일, 받는 파트너 이메일, 메모 | ② |
| 크레딧 | ④ 고객사 계약 | 파트너 | 계약일, 메모 | - (PoC 없이 시작 가능) |
| 크레딧 | ⑤ 파트너–Timely 계약 | 본사 | 계약일, 계약번호·메모 | ④ |
| 크레딧 | ⑥ 스페이스 지원 요청 | 파트너 | 스페이스 주소, 지급 희망일, 지급 크레딧 | ④⑤ |
| 크레딧 | ⑦ 스페이스·크레딧 지급 | 본사 | 지급일, 지급 크레딧, 메모 | ⑥ |

- 모든 기록은 확인 팝업을 거칩니다. 본사 단계는 결정 기록에도 남습니다.
- 스페이스 주소는 `timelyai.io/` 뒤 경로만 입력합니다. 영문자만 2~30자이고 소문자로 저장합니다(예: `timelyai.io/seoul`). 고객사 추가, ②, ⑥ 모두 같은 방식이며 앞 단계 주소가 다음 단계에 미리 채워집니다.
- 데모에서는 ③의 이메일을 실제로 보내지 않고 전달 기록만 남깁니다.

## 데이터와 권한

신청서, 딜, 심사 결과는 아티팩트 공유 저장소(`db`)에 저장됩니다. 그래서 다른 사람이 낸 신청서도 관리자 화면에 바로 나타납니다.

| 경로 | 쓰는 사람 | 보는 사람 |
|---|---|---|
| `accounts/<사용자>` (회원 정보, 비밀번호 해시) | 본인 | 본인, 관리자 |
| `applications/<신청자>` | 신청자 본인 | 신청자 본인, 관리자 |
| `deals/<파트너>/items/*` | 파트너 본인 | 파트너 본인, 관리자 |
| `deals/<파트너>/customers/*` (고객사와 파트너 단계 ①②④⑥) | 파트너 본인 | 파트너 본인, 관리자 |
| `partners/<파트너>` (심사 결과·등급·할인율), `…/dealReviews/*`, `…/rebates/*`, `…/customerReviews/*` (본사 단계 ③⑤⑦) | 관리자 | 파트너 본인, 관리자 |
| `log/*` (결정 기록: 판단 근거, 정량 지표, 내부 의견) | 관리자 | 관리자 |

- 관리자는 이 페이지의 편집 권한이 있는 사람입니다.
- 파트너는 심사 결과나 딜 승인 상태를 직접 바꿀 수 없습니다.

## 한계

- 공유 저장소를 쓰는 페이지는 **조직 내부 전용**입니다. 외부 회사가 실제로 신청하려면 별도 웹 서비스(서버, DB, 로그인)로 구현해야 합니다.
- 등급·할인율·딜 보호 수치는 [benchmark.md 5장 정책안](benchmark.md)을 따릅니다. 검토 중인 안입니다.
