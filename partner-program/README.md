# Timely Partner Network (검토용)

Timely AI · Timely Router 통합 파트너 프로그램 검토 자료입니다.

계약 구조는 **타임리 총계약 + 영업 이관 수수료**가 기본입니다(2026-11-26 반영). 타임리가 고객과 계약하고 대금을 받은 뒤 파트너에게 수수료를 지급합니다. 예전 자료의 "파트너 할인율"은 이 구조에서 "영업 이관 수수료율"을 뜻합니다. 근거는 사업팀 「협력사 정책 정리 (초안, 2026-11-25)」입니다.

## 회원 (데모)

| 기능 | 규칙 |
|---|---|
| 회원가입 | 회사 이메일만 허용(gmail·naver·daum·kakao 등 개인 메일 차단) → 6자리 인증 코드 → 이름·휴대폰·회사명·비밀번호·필수 동의 → 확인 팝업 → 가입 |
| 인증 코드 | 5분 유효, 재전송은 60초 뒤, 5회 틀리면 다시 받기 |
| 비밀번호 | 8자 이상, 영문·숫자·특수문자 모두 포함. 솔트를 붙인 SHA-256 해시로 저장(평문 저장 안 함) |
| 로그인 | ID = 회사 이메일. 5회 틀리면 5분 잠금 |
| ID 찾기 | 이름 + 휴대폰 번호 → 이메일 일부 가림(예: le*@hanbit-it.co.kr) |
| 비밀번호 찾기 | 회사 이메일 인증 코드 확인 → 새 비밀번호 → 확인 팝업 → 다시 로그인 |
| 로그인이 필요한 화면 | 파트너 신청, 파트너 포털 (관리자 화면은 페이지 편집 권한으로 판단) |

데모의 한계와 실제 서비스에서 바꿀 점:
- 인증 메일은 실제로 보내지 않습니다. 코드는 브라우저에서 만들어 화면의 "데모 메일함"에 보여 줍니다. 실제 서비스에서는 서버가 코드를 만들어 메일 발송 서비스로 보내고, 코드와 시도 횟수도 서버에서 검증해야 합니다.
- 비밀번호 해시 비교와 로그인 잠금이 브라우저에서 이뤄집니다. 실제 서비스에서는 서버에서 느린 해시(bcrypt, Argon2 등)로 처리해야 합니다.
- 계정은 claude.ai 사용자 한 명당 하나입니다(`accounts/<사용자>`).

## 고객사 진행 (PoC 스페이스 · 계약 · 정산)

모든 파트너에 공통으로 적용합니다. 고객 계약은 타임리가 맺습니다. 고객사마다 아래 8단계를 한 줄로 보여 주고, 지금 누가 무엇을 해야 하는지 배지로 표시합니다(예: "본사 처리 대기 · 타임리–고객 계약").

| 구분 | 단계 | 기록 주체 | 입력 항목 | 앞 단계 조건 |
|---|---|---|---|---|
| PoC | ① 고객사 협의 | 파트너 | 협의일, 메모 | - |
| PoC | ② PoC 스페이스 요청 | 파트너 | 스페이스 주소, 지급 희망일 | ① |
| PoC | ③ PoC 스페이스 전달 | 본사 | 전달일, 받는 파트너 이메일, 메모 | ② |
| 계약·지급 | ④ 계약 이관 요청 | 파트너 | 이관 요청일, 스페이스 주소, 지급 희망일, 계약 예정 금액(선택), 메모 | - (PoC 없이 시작 가능) |
| 계약·지급 | ⑤ 타임리–고객 계약 | 본사 | 계약일, 계약금액, 계약번호·메모 | ④ |
| 계약·지급 | ⑥ 스페이스·크레딧 지급 | 본사 | 지급일, 지급 크레딧, 메모 | ⑤ |
| 정산 | ⑦ 고객 대금 수금 | 본사 | 수금일, 수금액, 메모 | ⑤ |
| 정산 | ⑧ 수수료 지급 | 본사 | 지급일, 수수료 지급액, 산정 근거·메모 | ⑦ |

- 모든 기록은 확인 팝업을 거칩니다. 본사 단계는 결정 기록에도 남습니다.
- 스페이스 주소는 `timelyai.io/` 뒤 경로만 입력합니다. 영문자만 2~30자이고 소문자로 저장합니다(예: `timelyai.io/seoul`). 고객사 추가, ②, ④ 모두 같은 방식이며 앞 단계 주소가 다음 단계에 미리 채워집니다.
- 금액도 앞 단계 값이 미리 채워집니다. ⑤ 계약금액은 ④의 계약 예정 금액, ⑦ 수금액은 ⑤의 계약금액이 기본값입니다. ⑧ 수수료 지급액은 고객사명이 같은 승인 딜이 하나뿐이고 비율이 정해져 있을 때 "수금액 × 그 딜의 수수료율"로 채워집니다.
- 파트너 대시보드의 "지급받은 수수료"는 ⑧에 기록한 금액의 합계입니다. "예상 수수료 합계"는 파트너가 계약 완료로 바꾼 딜 금액에 수수료율을 곱한 값입니다.
- 계약 이관을 요청한 뒤에는 PoC 단계 버튼이 나오지 않습니다.
- 저장 키는 예전 이름을 그대로 씁니다(`contracted` = ④, `partnerContract` = ⑤). 예전 흐름으로 저장된 고객사는 ⑥까지 끝난 상태로 보이고 ⑦ 수금부터 이어집니다. 예전 ⑥ "스페이스 지원 요청" 단계는 없앴습니다.
- 데모에서는 ③의 이메일을 실제로 보내지 않고 전달 기록만 남깁니다.

## 견적서 (파트너 → 고객사)

구성과 계산은 참고 사이트를 정리한 [quote-reference.md](quote-reference.md)를 따릅니다.

> 새 계약 구조에서는 고객 계약과 가격을 타임리가 정합니다. 견적서를 타임리 명의로 발행할지, 파트너가 작성하고 타임리가 승인할지는 정해지지 않았습니다. 그래서 이 기능은 파트너가 공급자로 발행하던 방식 그대로 두었고, 견적서 탭 위에 그 안내를 띄웁니다.

- **진입**: 포털 "견적서" 탭의 "새 견적", 또는 "고객사 진행" 카드의 "견적서 작성"(고객명이 채워지고, 계약 전이면 선불 PoC, 계약 후면 Timely AI 유형이 기본값).
- **작성**: 1 기본 정보 → 2 추가 옵션 → 3 견적 확인. 오른쪽에 A4 견적서 미리보기가 입력할 때마다 바뀝니다.
- **유형**: 일반 라우터, 선불 PoC, Timely AI(항목별 견적, 계산 방식 4가지).
- **계산**: 참고 사이트와 같습니다. 선불 PoC 할인은 이용금액에만 적용하고, 부가세는 할인 후 금액의 10%를 원 단위로 반올림합니다. Timely AI는 항목 금액 반올림 → 할인 → 절사 → VAT 순서입니다. 참고 문서의 예시 3건과 금액이 일치하는 것을 확인했습니다.
- **상태**: 작성 중 → 발행본 저장. 발행본은 새 견적번호로 발행 당시 내용을 그대로 보관하고 고칠 수 없습니다. "복사하여 새 견적"으로 새 초안을 만듭니다.
- **견적번호**: `TPN-YYYYMMDD-XXXXXXXX`(한국 날짜 + 무작위 16진수 8자리). 직접 고칠 수 있습니다.
- **공급자 정보**: 파트너 신청서의 회사명·사업자등록번호·주소·전화와 로그인 계정의 이름·이메일이 기본값이고, "견적서 설정"에서 견적마다 바꿀 수 있습니다.
- **로고**: "견적서 설정"에서 없음 / 타임리 AI 로고 / 직접 올리기 중에 고릅니다. 올린 이미지(PNG·JPG·WEBP)는 400×120 안으로 줄여 견적에 함께 저장하고, 견적서 왼쪽 위에 최대 높이 48px로 들어갑니다. "기본 로고로 저장"을 누르면 새 견적부터 그 로고가 기본으로 들어갑니다(`deals/<파트너>/quoteDefaults/main`).
- **파일 저장**: "견적서 파일 저장"은 인쇄용 HTML 파일을 내려받습니다. 브라우저로 열어 인쇄하면 PDF로 만들 수 있습니다. 이 페이지 안에서는 인쇄 창을 띄울 수 없어 이 방식으로 했습니다.
- **관리자 보기**: 관리자 "발행 견적서" 메뉴에서 모든 파트너의 발행본을 한 줄씩 봅니다. 고객명·견적번호·파트너 검색, 유형·파트너 필터, 조회 결과 금액 합계가 있고, 열면 발행 당시 견적서를 그대로 보여 주며 파일로 저장할 수 있습니다. 초안은 나오지 않고 고칠 수 없습니다.
- **참고 사이트와 다른 점**: 비교안별 견적, 견적서 컬럼 편집, JSON 파일 저장·불러오기, 후속 담당자 인수인계, 변경 이력은 넣지 않았습니다. 참고 사이트에서 확인하지 못한 부분(개발 비용 품명, 세부 조건이 견적서에 나오는 모양)은 "개발 비용", 기타사항에 "라벨 : 값" 한 줄씩으로 정했습니다.

## 공식 파트너 배지

- 등급별 3종(Registered / Advanced / Premier), 영문 "TimelyAI | OFFICIAL PARTNER · 등급" 구성입니다. 디자인 시스템의 타임리 로고와 브랜드 보라(`#5e0aff`)로 페이지에서 직접 그려 PNG로 만듭니다. 바탕은 Registered 흰색, Advanced 옅은 보라, Premier 보라입니다.
- 쓰이는 곳: 프로그램 소개의 등급 카드, 파트너 포털 머리말과 "파트너 정보" 탭(이미지 저장, 사용 안내), 견적서 설정의 로고 선택지 "공식 파트너 배지".
- 견적서에는 발행 당시 등급만 저장하고 그림은 볼 때 다시 그립니다.
- 이 배지는 데모용 시안입니다. 실제로 쓰려면 브랜드 담당자의 확인과 사용 규정이 필요합니다.

## 데이터와 권한

신청서, 딜, 심사 결과는 아티팩트 공유 저장소(`db`)에 저장됩니다. 그래서 다른 사람이 낸 신청서도 관리자 화면에 바로 나타납니다.

| 경로 | 쓰는 사람 | 보는 사람 |
|---|---|---|
| `accounts/<사용자>` (회원 정보, 비밀번호 해시) | 본인 | 본인, 관리자 |
| `applications/<신청자>` | 신청자 본인 | 신청자 본인, 관리자 |
| `deals/<파트너>/items/*` | 파트너 본인 | 파트너 본인, 관리자 |
| `deals/<파트너>/customers/*` (고객사와 파트너 단계 ①②④) | 파트너 본인 | 파트너 본인, 관리자 |
| `deals/<파트너>/quotes/*` (견적 초안과 발행본) | 파트너 본인 | 파트너 본인, 관리자 |
| `partners/<파트너>` (심사 결과·등급·수수료율), `…/dealReviews/*`, `…/rebates/*`, `…/customerReviews/*` (본사 단계 ③⑤⑥⑦⑧) | 관리자 | 파트너 본인, 관리자 |
| `log/*` (결정 기록: 판단 근거, 정량 지표, 내부 의견) | 관리자 | 관리자 |

- 관리자는 이 페이지의 편집 권한이 있는 사람입니다.
- 파트너는 심사 결과나 딜 승인 상태를 직접 바꿀 수 없습니다.

## 한계

- 공유 저장소를 쓰는 페이지는 **조직 내부 전용**입니다. 외부 회사가 실제로 신청하려면 별도 웹 서비스(서버, DB, 로그인)로 구현해야 합니다.
- 등급·수수료율·딜 보호 수치는 [benchmark.md 5장 정책안](benchmark.md)을 따릅니다. 검토 중인 안입니다.
