# 참고 사이트 구조: Timely 견적 관리 시스템

파트너 포털에 "파트너가 고객사에게 발급하는 견적서" 기능을 만들 때 참고할 사이트의 화면·입력 항목·계산·문서 구성을 정리한 문서입니다.

- 확인일: 2026-11-18
- 확인 방법: 로그인된 크롬으로 화면을 직접 조작해 봤고, 계산 규칙은 사이트가 브라우저에 내려주는 스크립트(`/src/*.js`)도 함께 읽었습니다.
- 지킨 것: 저장·발행·삭제·인수인계 버튼은 누르지 않았습니다. 서버로 나간 요청은 조회(GET)뿐입니다. 입력값은 모두 저장하지 않은 임시값입니다.
- 표기: **[화면]** 직접 본 것, **[코드]** 스크립트에서 읽었지만 화면으로는 확인하지 않은 것, **[추정]** 근거가 약한 것, **[확인 못 함]** 볼 수 없었던 것.
- 가명: 내역에 있던 고객사는 "고객사 A"로, 로그인한 직원의 이름·이메일은 "(직원 이름)", "(직원 이메일)"로 바꿔 적었습니다.
- 캡처: 모든 주요 화면에 로그인한 직원의 이름과 이메일이 보여서 PNG는 저장하지 않았습니다.

## 1. 한눈에 보기

| 항목 | 내용 |
|---|---|
| 성격 | 타임리 직원이 고객사에게 줄 견적서를 만드는 내부 도구. 한 화면에서 입력하면 오른쪽에 A4 견적서가 바로 그려짐 |
| 견적 유형 | 일반 라우터, 선불 PoC, Timely AI (유형에 따라 입력 항목·품목·계산이 달라짐) |
| 작성 단계 | 1 기본 정보 → 2 추가 옵션 → 3 견적 확인 |
| 저장 | 자동 저장 없음. "공동 초안 저장"(작성 중) 또는 "발행본 저장"(발행)을 눌러야 서버에 저장 |
| 출력 | "PDF 저장 / 인쇄"는 브라우저 인쇄 창을 띄움. 메일 발송 기능은 없음 |
| 상태 | 작성 중(`draft`) → 발행본 저장(`issued`) 두 가지 |

## 2. 화면 목록과 이동 흐름

| 화면 | 주소 | 들어가는 길 |
|---|---|---|
| 로그인 | `/login` | 로그인 안 된 상태로 접속 |
| 견적 작성 (기본 화면) | `/` | 로그인 직후 |
| 견적서 설정 (대화상자) | `/` 위에 뜸 | 상단 "견적서 설정" |
| 견적 내역 | `/` 안에서 화면 전환 | 상단 "견적 내역" |
| 견적 상세 (내역 아래에 펼쳐짐) | 〃 | 내역 표의 "열기" |
| 저장된 발행본 조회 | 〃 | 상세의 "발행본 조회" |
| 비밀번호 변경 / 로그아웃 | `/account` | 화면 맨 아래 링크 |
| 직원 계정 관리 | `/admin` | 화면 맨 아래 링크 |

**[화면]** 흐름

- 견적 작성 → "견적 내역" → "열기" → "초안 열기"를 누르면 그 견적이 작성 화면에 다시 열립니다.
- 견적 내역 → "열기" → "발행본 조회" → "내역으로" 또는 "복사하여 새 견적".
- 견적 내역 → "견적 작성으로"를 누르면 작성 화면으로 돌아갑니다.
- 주소(URL)는 작성·내역·발행본 조회 사이에서 바뀌지 않습니다. 한 페이지 안에서 영역만 바꿔 보여 줍니다.

**[화면]** 왼쪽에 로고 "timely"와 "Timely 견적 관리 시스템", 오른쪽에 버튼 네 개가 있습니다.

| 버튼 | 동작 |
|---|---|

## 4. 견적 작성 화면

화면이 좌우로 나뉩니다.

- 왼쪽: 입력 영역. 맨 위에 단계 버튼 "1 기본 정보", "2 추가 옵션", "3 견적 확인"이 있고, 현재 단계에 밑줄이 그어집니다.
- 오른쪽: "견적서 미리보기 · A4". 입력할 때마다 바로 다시 그려집니다.
- 왼쪽 아래에는 항상 "총 견적금액 (VAT 포함)"과 금액, 그리고 단계 이동 버튼이 있습니다.
- 안내 문구 두 줄이 항상 보입니다.
  - "자동 저장하지 않습니다. 공동 저장 또는 파일 저장 버튼을 눌러 보관하세요."
  - "회사 공동 저장소에 연결되었습니다. 저장 버튼을 눌러야 전송됩니다." (연결 상태 표시)

**[화면]** 고객명을 비운 채 2단계로 가려 하면 이동하지 않고, 고객명 칸 테두리가 빨갛게 바뀌며 바로 아래에 "고객명을 입력해 주세요."가 나옵니다. 같은 문구가 미리보기의 기타사항에도 "▷ 입력 확인 필요 : 고객명을 입력해 주세요."로 나옵니다.

**[코드]** 1단계 검사 문구

| 조건 | 문구 |
|---|---|
| 고객명 없음 | 고객명을 입력해 주세요. |
| 금액이 1원~1조 원의 정수가 아님 (Timely AI 제외) | 1원부터 1조 원까지, 원 단위로 입력해 주세요. |

| 종료일 없음 | 이용 종료일을 선택해 주세요. |
| 종료일이 시작일보다 앞 | 종료일은 시작일 이후로 선택해 주세요. |

### 4.3 2단계: 추가 옵션 (Timely AI)

**담당자**: "발신 담당자"만 있습니다. 플랫폼·지원·개발 체크는 없습니다.

**문서 정보 · 할인 · 세부 조건** (접힌 영역)

- 담당자 · 문서 정보: 견적번호, 견적일, 견적 유효일 (4.2와 같음)
- Timely AI 구성. 도움말 "단가는 직접 확인해 입력하세요. 비교안은 합산하지 않고 각각 출력합니다."

| 라벨 | 입력 형태 | 기본값 | 비고 |
|---|---|---|---|
| 견적금액 할인 (원) | 숫자 | 0 | 도움말 "입력한 할인액을 견적금액에서 차감합니다. 할인율은 할인 전 금액 대비로 표시합니다." |
| AI 견적 구성 | 선택 | 항목별 견적 | 항목별 견적 / 비교안별 견적 |

항목마다 아래 칸이 반복됩니다(라벨 끝에 항목 번호가 붙음).

| 라벨 | 입력 형태 | 기본값 | 비고 |
|---|---|---|---|
| 품명 N | 글자 | 빈칸 | |
| 계산 방식 N | 선택 | 수량 × 단가 | 수량 × 단가 / 총금액 직접 입력 / 인원 × 월 제공량 × 개월 × 단가 / 기간형 총금액 직접 입력 |
| 수량 / 인원 N | 숫자 | 1 | 소수 허용 |
| 1인 월 제공량 N | 숫자 | 1 | 계산 방식이 "인원 × 월 제공량 × 개월 × 단가"일 때 나타남 |
| 개월 N | 숫자 | 1 | 〃 |
| 입력 단가 N | 숫자 | 0 | 소수 허용 (33333.5 입력 확인) |
| 비고 N | 글자 | 빈칸 | |

- 항목마다 "항목 삭제", 목록 끝에 "항목 추가" 버튼이 있습니다.
- **[코드]** 항목은 최대 30개. 숫자는 0 이상, 소수 넷째 자리까지. 항목 금액은 1조 원 이하.
- **[코드]** "비교안별 견적"을 고르면 비교안(기본 이름 "1안", 단위 "크레딧", 기간형 계산) 목록을 편집하고, 견적서에는 비교안을 합산하지 않고 각각 출력합니다. 총 견적금액에는 첫 번째 비교안만 반영됩니다. 이 모드의 화면은 열어 보지 않았습니다.

### 4.4 3단계: 견적 확인

## 6. 품목과 계산

단가표나 품목 관리 화면은 없습니다. 품목은 유형에 따라 고정되어 있거나(라우터·PoC), 담당자가 직접 적습니다(Timely AI).

### 6.1 일반 라우터 · 선불 PoC의 품목 **[화면]**

| 품번 | 품명 | 수량 | 단위 | 단가·금액 | 비고 | 나오는 조건 |
|---|---|---|---|---|---|---|
| 1 | Router 예상 이용금액 (일반 라우터) / 선납 PoC 이용예산 (선불 PoC) | 1 | 사용량 | 1단계에서 넣은 금액 | VAT 별도 | 항상 |
| 2 | Router 플랫폼 이용료 | 1 | 식 | 플랫폼 이용료 | 별도 합의 | 체크했을 때 |
| 3 | 지원 서비스 | 1 | 식 | 지원 서비스 비용 | 별도 합의 | 체크했을 때 |
| 4 | (개발 비용 항목. 품명은 확인 못 함) | 1 | 식 | 개발 비용 | 별도 합의 **[추정]** | 체크했을 때 |

### 6.2 일반 라우터 · 선불 PoC의 계산 **[코드 + 화면 예시로 확인]**

```
이용금액   = 1단계 금액 (0~1조 원 정수)
고정비     = 체크한 플랫폼 이용료 + 지원 서비스 비용 + 개발 비용
할인율     = 선불 PoC이고 할인율이 "별도 협의"가 아닐 때만 그 값(%), 그 밖에는 0
할인액     = 이용금액 × 할인율 ÷ 100, 원 단위 반올림(0.5는 올림)   ← 고정비에는 적용 안 함
공급가액   = 이용금액 + 고정비 − 할인액
부가세     = 공급가액 ÷ 10, 원 단위 반올림
최종 금액  = 공급가액 + 부가세
```

- 일반 라우터의 "사용단가 할인율"은 견적 금액을 줄이지 않습니다. 실제 정산 때 적용하는 조건으로만 적습니다.
- 합계 줄 표기
  - 일반 라우터: 공급가액 / 부가가치세 / 최종 견적 금액
  - 선불 PoC, 할인 없음: 공급가액 / 부가세 / 최종 견적 금액
  - 선불 PoC, 할인 있음: 공급가액 (할인 전) / 선납 할인 금액 (10%) / 부가세 (할인 후 기준) / 최종 견적 금액

**확인한 예시 1 (일반 라우터)**: 이용금액 1,234,567 + 플랫폼 이용료 300,000 + 지원 서비스 150,000

| 줄 | 값 |
|---|---|
| 공급가액 | 1,684,567원 |
| 부가가치세 | 168,457원 (168,456.7을 반올림) |
| 최종 견적 금액 | 1,853,024원 |

**확인한 예시 2 (선불 PoC, 같은 입력에 할인율 10%)**

| 줄 | 값 |
|---|---|
| 공급가액 (할인 전) | 1,684,567원 |
| 선납 할인 금액 (10%) | −123,457원 (1,234,567의 10% = 123,456.7을 반올림. 고정비 450,000에는 적용 안 됨) |
| 부가세 (할인 후 기준) | 156,111원 (1,561,110 ÷ 10) |
| 최종 견적 금액 | 1,717,221원 |

### 6.3 Timely AI의 계산 **[코드 + 화면 예시로 확인]**

항목 금액

| 계산 방식 | 금액 | 견적서의 수량 | 견적서의 단가 |
|---|---|---|---|
| 수량 × 단가 | 수량 × 입력 단가 | 수량 | 입력 단가 |
| 총금액 직접 입력 | 입력한 총금액 | 수량 | 총금액 ÷ 수량 |
| 인원 × 월 제공량 × 개월 × 단가 | 인원 × 월 제공량 × 개월 × 입력 단가 | 인원 × 월 제공량 × 개월 | 입력 단가 |
| 기간형 총금액 직접 입력 | 입력한 총금액 | 인원 × 월 제공량 × 개월 | 총금액 ÷ 수량 |

항목 금액은 각각 원 단위로 반올림합니다(0.5는 올림).

```
소계       = 항목 금액 합
할인 후    = 소계 − 견적금액 할인(원)          ← 할인은 소계 이내의 원 단위
절사 후    = 할인 후를 절사 단위로 내림
VAT 10% 별도 : 공급가액 = 절사 후,              부가세 = 공급가액 ÷ 10 반올림
VAT 포함     : 공급가액 = 절사 후 × 10 ÷ 11 반올림, 부가세 = 절사 후 − 공급가액
VAT 0%       : 공급가액 = 절사 후,              부가세 = 0
최종 금액  = 공급가액 + 부가세
```

견적서 기타사항에 이 순서가 "항목 금액 원 단위 반올림 → 할인금액 차감 → 절사 → VAT 계산. 기간 계산은 기간형 계산에서만 적용."으로 적힙니다.

**확인한 예시 3**: 품명 1개, 수량 3 × 단가 33,333.5 → 항목 금액 100,001원 (100,000.5를 반올림)

| 설정 | 공급가액 | 부가가치세 | 최종 견적 금액 |
|---|---|---|---|
| VAT 별도, 절사 1 | 100,001원 | 10,000원 | 110,001원 |
| VAT 별도, 절사 1000 | 100,000원 | 10,000원 | 110,000원 |
| VAT 포함, 절사 1000 | 90,909원 | 9,091원 | 100,000원 |

VAT 포함일 때 합계 줄은 "할인 전 금액 (VAT 포함) 100,001원 / 절사 금액 −1원 / 공급가액 / 부가가치세 / 최종 견적 금액" 순이고, 기타사항에 "할인 0원 / 절사 1원"이 추가됩니다. VAT 별도에서 절사가 있을 때 "절사 금액" 줄이 따로 나오는지는 확인하지 못했습니다.

## 7. 견적번호 · 유효기간 · 상태 흐름

| 항목 | 규칙 | 근거 |
|---|---|---|
| 견적번호 | `TIME-YYYYMMDD-XXXXXXXX`. 날짜 8자리 뒤에 무작위 16진수(0-9, A-F) 8자리(예: `TIME-20261118-DDA7519C`). 새 견적을 열 때 자동 생성되고 직접 고칠 수 있음. 날짜는 세계 표준시 기준이라 한국 시간 오전 9시 전에는 전날 날짜가 붙음 | 화면 + 코드 |

| 견적일 | 오늘 | 화면 |
| 견적 유효일 | 견적일 + 7일. 견적서에 "견적 유효기간 : YYYY-MM-DD까지" | 화면 |
| 이용기간 | 시작일 = 오늘, 종료일 = 시작일 + 30일 | 화면 |

1. 작성 화면에서 입력 (서버에 아무것도 저장되지 않음)

4. 발행본은 고치지 않고, "복사하여 새 견적"으로 새 초안을 만듦. 복사본은 원본 발행본과 연결되어 상세에 "원본 발행본 보기" 버튼이 생김 **[코드]**

- **[코드]** 다른 사람이 먼저 고친 초안을 덮어쓰지 않도록, 저장할 때 내가 읽은 수정 버전 번호를 함께 보냅니다.

- 승인 단계는 화면에 없습니다. 스크립트에는 제품·조건·재무 확인 같은 발행 전 점검 항목이 남아 있지만 화면에는 나오지 않습니다 **[코드]**.

- 위쪽 줄: "발행본 번호 · 저장된 발행본" + "내역으로", "저장된 발행본 PDF", "복사하여 새 견적"

- **[코드]** 발행할 때 화면에 그려진 견적서 모양을 통째로 저장해 두었다가 그대로 다시 그립니다. 그래서 나중에 견적서 양식이 바뀌어도 예전 발행본은 예전 모양으로 보입니다. 실제로 10월 발행본은 지금 양식과 문구가 조금 달랐습니다("견적 합계", "견적금액: … / VAT 포함 / 원화 기준").
- "저장된 발행본 PDF"는 브라우저 인쇄 창을 띄웁니다 **[코드]**.

## 11. 견적서 문서 구성 **[화면]**

A4 한 장, 위에서부터 다음 순서입니다.

**① 공급자 머리말** (오른쪽 정렬 상자)

- 공급자명 (굵게)
- 사업자등록번호 : …
- 주소 : …
- TEL : …

**② 문서 정보 표**

| 왼쪽 | | 오른쪽 | |
|---|---|---|---|
| 건 명 | 유형별 건명 (한 줄 전체) | | |
| 견적일 | YYYY-MM-DD | 견적번호 | TIME-… |
| 수 신 | 고객명 | 담당자 | 고객 담당자 |
| 연락처 | 고객 담당자 전화번호 | E-mail | 고객 이메일 |
| 발 신 | 공급자명 | 담당자 | 발신 담당자 |
| 연락처 | 공급자 전화 | E-mail | 발신 이메일 |
| 이용기간 | 시작일 ~ 종료일 (한 줄 전체) | | |

- 비어 있는 값은 "—"로 나옵니다. 고객명이 비면 "고객명"이라는 글자가 그대로 나옵니다.
- 건명 기본값: "Timely Router 이용 견적" / "Timely Router 선불 PoC 이용 견적" / "Timely AI 이용 견적". 설정의 "건명"을 채우면 그 값을 씁니다 **[추정]**.

**③ "1. 견적 세부내용"**

- 품목 표: 품번 / 품명 / 수량 / 단위 / 단가 (원) / 금액 (원) / 비고
- 표 아래 합계 줄 (오른쪽 정렬, 마지막 줄 굵게): 6장의 유형별 표기를 따름
- "기타사항" 상자. 줄마다 "▷"로 시작

| 줄 | 나오는 조건 |
|---|---|
| 유형별 조건 문구 (아래) | 항상 |
| 견적 유효기간 : YYYY-MM-DD까지 | 항상 |
| 입력 확인 필요 : (검사 문구) | 검사 오류가 있을 때 |
| 선택 서비스 범위 : (서비스 범위 및 기간) | 값이 있을 때 |
| 참고 환율 : 1400원/USD (기준일, 출처). 추정용이며 고정환율 또는 사용량 보장이 아닙니다. | 환율 표시를 켰을 때 |
| 가격 근거: … / 계산 순서 문구 / 할인 N원 / 절사 N원 | Timely AI ("▷" 없이 출력) |

유형별 조건 문구

- 일반 라우터: "본 견적은 예상 이용금액이며 실제 이용량에 따라 정산합니다. 이용 및 정산 조건은 별도 합의합니다."
- 선불 PoC: "본 견적은 선불 PoC 이용 제안이며, 이용 및 정산 조건은 별도 합의합니다."
- Timely AI: "상품 구성과 단가는 담당자 입력 기준의 제안이며, 이용 조건은 별도 합의합니다."

이용 모델, 공급경로, 별도 단가표, 수수료 제안, 잔액·환급·연장 제안, 무상 이용금액, 기타 제안사항을 채웠을 때 견적서 어디에 어떻게 나오는지는 확인하지 못했습니다.

**④ "2. 견적 금액"** (상자 안 가운데 정렬)

- ③의 합계 줄과 같은 항목을 "항목 : 금액" 형태로 한 줄씩 반복합니다. 예: "공급가액 : 1,684,567원", "부가가치세 : 168,457원", "최종 견적 금액 : 1,853,024원"
- 선불 PoC에 할인이 있으면 "공급가액 (할인 전)", "선납 할인 금액 (10%)", "부가세 (할인 후 기준)", "최종 견적 금액" 네 줄이 됩니다.
- 맨 아래 한 줄: "본 견적은 계약 체결 또는 발송 완료를 의미하지 않습니다."

직인, 서명란, 은행 계좌, 결제 조건 칸은 없습니다.

## 14. 파트너 포털로 옮길 때 눈여겨볼 점 (제안)

참고 사이트는 "타임리 → 고객사" 견적이고, 만들려는 것은 "파트너 → 고객사" 견적입니다. 아래는 화면을 보며 든 생각이고 정해진 사항이 아닙니다.

- 공급자 머리말과 "발 신" 칸은 타임리가 아니라 파트너 회사 정보(파트너 신청서의 회사명·사업자등록번호·주소·전화, 담당자 이름·이메일)로 채우면 됩니다. 참고 사이트도 이 값을 견적마다 설정에서 바꿀 수 있게 해 두었습니다.
- "수 신"은 고객사 진행 카드의 고객사 정보를 미리 채울 수 있습니다.
- 세 유형 가운데 고객사 진행 7단계와 바로 맞닿는 것은 선불 PoC(PoC 단계)와 Timely AI 항목별 견적(크레딧 단계)입니다.
- 참고 사이트의 선불 할인율 선택지는 5/8/10/12/100으로 고정이지만, 파트너 데모는 파트너별 할인 구간표를 따로 두고 있어 그대로 옮기면 맞지 않습니다.
- 상태는 작성 중 → 발행본 저장 두 단계뿐이고, 발행본은 고치지 않고 복사해서 새로 만듭니다. 발행본은 발행 당시 모양을 통째로 보관합니다.
- 모든 저장·발행에 "자동 저장하지 않음"과 "외부 발송을 의미하지 않음"을 반복해서 알려 줍니다. 파트너 데모의 "제출·확정 전 확인 팝업" 원칙과 같은 방향입니다.
